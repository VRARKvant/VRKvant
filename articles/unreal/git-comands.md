### 1. Первоначальная настройка (Config)

Задают данные автора для истории коммитов и параметры по умолчанию.

```bash
# Указать имя и email автора (глобально для всех репозиториев)
git config --global user.name "Имя Фамилия"
git config --global user.email "email@example.com"

# Задать имя главной ветки по умолчанию (main вместо master)
git config --global init.defaultBranch main

# Просмотреть все текущие настройки
git config --list

```

### 2. Создание и получение репозитория

```bash
# Инициализировать новый локальный репозиторий в текущей папке
git init

# Склонировать удалённый репозиторий на свой компьютер
git clone <url_репозитория>

```

---

### 3. Базовый рабочий процесс (Индексация и коммиты)

```bash
# Проверить состояние файлов (изменённые, подготовленные, неотслеживаемые)
git status

# Добавить конкретный файл в индекс (Staging Area)
git add <имя_файла>

# Добавить все изменённые и новые файлы в индекс
git add .

# Зафиксировать изменения с сообщением
git commit -m "Понятное описание изменений"

# Добавить все отслеживаемые изменённые файлы и сразу сделать коммит (минуя отдельный git add)
git commit -am "Описание изменений"

# Просмотреть разницу между рабочей директорией и индексом
git diff

# Просмотреть разницу между проиндексированными файлами и последним коммитом
git diff --staged

```

### 4. Ветки (Branches)

В современных версиях Git для переключения рекомендуется команда `git switch` (вместо перегруженной `git checkout`).

```bash
# Список локальных веток (* указывает на текущую)
git branch

# Список всех веток, включая удалённые
git branch -a

# Создать новую ветку (без перехода на неё)
git branch <имя_ветки>

# Переключиться на существующую ветку
git switch <имя_ветки>

# Создать новую ветку и сразу переключиться на неё
git switch -c <имя_ветки>
# (Устаревший аналог: git checkout -b <имя_ветки>)

# Переименовать текущую ветку
git branch -m <новое_имя>

# Удалить ветку (только если она уже влита)
git branch -d <имя_ветки>

# Принудительно удалить ветку (даже с невзятыми изменениями)
git branch -D <имя_ветки>

```

### 5. Слияние и перебазирование (Merge & Rebase)

```bash
# Влить указанную ветку в текущую активную ветку
git merge <имя_ветки>

# Прервать слияние при возникновении неразрешимого конфликта
git merge --abort

# Перебазировать текущую ветку поверх целевой (линейная история)
git rebase <имя_ветки>

# Продолжить rebase после разрешения конфликтов
git rebase --continue

# Прервать процесс rebase и вернуть исходное состояние
git rebase --abort

```

### 6. Удалённые репозитории (Remotes & Sync)

```bash
# Показать список привязанных удалённых репозиториев
git remote -v

# Привязать удалённый репозиторий (обычно под именем origin)
git remote add origin <url_репозитория>

# Загрузить изменения с сервера без автоматического слияния
git fetch origin

# Загрузить изменения и автоматически слить их с текущей веткой
git pull origin <ветка>

# Отправить ветку на сервер и связать её с удалённой (tracking)
git push -u origin <ветка>

# Обычная отправка коммитов (если связь уже установлена)
git push

# Удалить ветку на удалённом сервере
git push origin --delete <имя_ветки>

```

### 7. История и инспекция

```bash
# Компактный лог коммитов в одну строку с деревом ветвлений
git log --oneline --graph --all

# Показать последние N коммитов
git log -n 5

# Показать подробные изменения в конкретном коммите
git show <хэш_коммита>

# Показать построчно, кто и когда изменил конкретный файл
git blame <имя_файла>

```

### 8. Отмена изменений и откат (Undo)

```bash
# Отменить незакоммиченные правки в файле (вернуть к состоянию последнего коммита)
git restore <имя_файла>

# Убрать файл из индекса (unstage), оставив изменения в коде
git restore --staged <имя_файла>

# Исправить последний коммит (добавить забытые файлы или изменить текст)
git commit --amend -m "Новое сообщение"

# Безопасный откат: создать новый коммит, который отменяет изменения указанного
git revert <хэш_коммита>

# Мягкий откат коммита (коммит удаляется, но изменения остаются в индексе)
git reset --soft HEAD~1

# Жёсткий откат (безвозвратно удаляет коммиты и все изменения в коде)
git reset --hard <хэш_коммита_или_HEAD~1>

```

### 9. Временное сохранение (Stash)

Позволяет спрятать незавершённые изменения, чтобы быстро переключить ветку без создания промежуточного коммита.

```bash
# Спрятать текущие изменения в карман (stash)
git stash

# Спрятать изменения с понятной заметкой
git stash save "черновик авторизации"

# Посмотреть список всех сохранённых записей
git stash list

# Применить последние сохранённые изменения и удалить их из списка stash
git stash pop

# Применить изменения, но оставить запись в списке stash
git stash apply

# Очистить весь список stash
git stash clear

```

### 10. Аварийные инструменты

```bash
# Журнал всех действий с указателем HEAD (позволяет найти потерянные коммиты после неудачного reset или rebase)
git reflog

# Удалить неотслеживаемые файлы и папки из рабочей директории
git clean -fd

```
