## Зачем нужен Git LFS (Large File Storage)?

Обычный **Git** отслеживает изменения строка за строкой в текстовых файлах. При изменении `.uasset` на 100 МБ Git сохраняет новую полную копию файла в истории `.git/objects`.

**Git LFS** решает эту проблему:
- Бинарные файлы хранятся на отдельном LFS-сервере.
- В самом Git-репозитории хранятся только крошечные **текстовые указатели** (Pointer files) с SHA-256 хешем файла и его размером.
- При выполнении `git checkout` или `git pull` скачиваются только нужные версии ассетов для текущей рабочей ветки.

## Установка Git и Git LFS

1. Скачайте и установите [Git for Windows](https://git-scm.com/).
2. Откройте командную строку ([Terminal](https://apps.microsoft.com/detail/9n0dx20hk701?hl=ru-RU&gl=RU) / PowerShell / Git Bash) и выполните инициализацию LFS:


```bash
git lfs install
```

При успешной установке вы увидите сообщение: `Git LFS initialized.`

## Подключение Source Control внутри Unreal Engine 5

В Unreal Engine 5 есть удобный встроенный инструмент управления версиями **Revision Control**.

### Пошаговая настройка:

1. Внизу справа в редакторе UE5 найдите кнопку **Revision Control**
![](img/unreal/connect_to_revision_control.png) 
2. В выпадающем списке **Provider** выберите **Git**.
3. Укажите путь к бинарному файлу Git (`git.exe`), если он не определился автоматически.
4. Отметьте галочками:
   - `Add new files to Revision Control automatically` (Автоматически добавлять новые ассеты под контроль версий).
   - `Use Git LFS` (Использовать Git LFS).
5. Укажите URL вашего репозитория на github
6. Нажмите **Accept Settings**.
![](img/unreal/initialize_project_with_git.jpg) 

Теперь прямо из Content Browser вы можете:
- Смотреть историю изменений ассета (`History`).
- Сравнивать версии Блупринтов (`Diff`).
- Делать коммиты отдельных файлов через контекстное меню.
![](img/unreal/revision_control.png)

### Github

1. После создания репозитория у вас будет вот такое окно
2. Тут есть URL на репозиторий
3. И команды которые нужно выполнить для того чтобы отправить проект на репозиторий
![](img/unreal/github_create_rep.png)

После этого будет достаточно делать `git push` после коммитов

```bash
git push
```

## Настройка `.gitignore` и `.gitattributes`

Для проектов Unreal Engine **критически важно** игнорировать временные файлы генерации и бинарники сборки (папки `Intermediate`, `Saved`, `DerivedDataCache`, `Binaries`).

### `.gitignore`

```gitignore
# Unreal Engine Temp & Generated Folders
/Binaries/
/DerivedDataCache/
/Intermediate/
/Saved/
/Build/
/.vs/
/.idea/
/.vscode/
*.xcworkspace
*.xcodeproj
*.sln
*.suo
*.opensdf
*.sdf
*.VC.db
*.VC.opendb

# Autogenerated C++ files
/Plugins/*/Intermediate/
/Plugins/*/Binaries/

# OS Specific
.DS_Store
Thumbs.db
```

### `.gitattributes`

Файл `.gitattributes` сообщает Git, какие типы файлов должны обрабатываться через Git LFS.

```gitattributes
# Unreal Engine Binary Assets (LFS)
*.uasset filter=lfs diff=lfs merge=lfs -text
*.umap filter=lfs diff=lfs merge=lfs -text

# 3D Graphics & Animations
*.fbx filter=lfs diff=lfs merge=lfs -text
*.obj filter=lfs diff=lfs merge=lfs -text
*.blend filter=lfs diff=lfs merge=lfs -text
*.max filter=lfs diff=lfs merge=lfs -text
*.maya filter=lfs diff=lfs merge=lfs -text

# Textures & Media
*.png filter=lfs diff=lfs merge=lfs -text
*.tga filter=lfs diff=lfs merge=lfs -text
*.jpg filter=lfs diff=lfs merge=lfs -text
*.jpeg filter=lfs diff=lfs merge=lfs -text
*.exr filter=lfs diff=lfs merge=lfs -text
*.psd filter=lfs diff=lfs merge=lfs -text
*.hdr filter=lfs diff=lfs merge=lfs -text

# Audio & Video
*.wav filter=lfs diff=lfs merge=lfs -text
*.mp3 filter=lfs diff=lfs merge=lfs -text
*.ogg filter=lfs diff=lfs merge=lfs -text
*.mp4 filter=lfs diff=lfs merge=lfs -text

# Compiled Plugins & Binaries
*.dll filter=lfs diff=lfs merge=lfs -text
*.so filter=lfs diff=lfs merge=lfs -text
*.dylib filter=lfs diff=lfs merge=lfs -text
*.exe filter=lfs diff=lfs merge=lfs -text
```

## Решение конфликтов и специфические особенности бинарных файлов

### Почему бинарные `.uasset` нельзя замержить вручную?
Текстовый merge в Git объединяет строки кодов. В бинарных файлах нет строк. Если два разработчика одновременно изменят один и тот же файл `.uasset` или `.umap` в разных ветках, классический `git merge` вызовет конфликт, который сломает файл!

### Как работать безопасно:
1. **Командное правило "Один файл - один разработчик":** Перед редактированием уровня `.umap` или важного Blueprint согласуйте это с командой.
2. **Встроенный UE Blueprint Diff Tool:** Unreal Engine умеет визуально сравнивать ветви Блупринтов! Выберите ассет -> `Revision Control` -> `Diff` для сравнения двух коммитов.
3. **Использование File Locking (LFS Lock):** На сервисах GitHub / GitLab / Azure DevOps вы можете включить блокировку файлов:
   ```bash
   git lfs lock Content/Maps/MainLevel.umap
   ```
   Это запретит другим участникам отправлять изменения в этот файл, пока вы не снимите блокировку:
   ```bash
   git lfs unlock Content/Maps/MainLevel.umap
   ```
